# 真实向量检索阶段设计

## 目标与方案

DeepSeek 负责回答，本地 Ollama qwen3-embedding:0.6b 生成原生 1024 维向量，PGVector 负责检索。用户已明确不使用阿里云模型，当前运行流程只需要 DeepSeek Key。

数据库新增 embedding_local vector(1024)，保留原 embedding vector(1536) 和历史数据，避免改变维数导致原向量丢失。本地模型可使用 CPU，但需首次下载，模型文件约 639 MB。

## 数据流与边界

文档文本按段落及最长 800 字符切块，长段落保留 100 字符重叠。新文档和上传文档均经过分块。本地请求使用 Ollama /api/embed，校验 1024 维；可选远端请求明确指定 dimensions=1536、encoding_format=float。拒绝空文本、错误维数、非数值、非有限值及零向量，服务错误转成不含上游响应的中文提示，不退回演示向量。

向量来源标记由模式、模型、接口地址摘要和维数构成。数据库增量添加 embedding_identity 字段，旧数据保持 NULL，不猜测旧模型；检索仅使用当前来源与对应维数列的向量。接口地址改变会要求重建，即使实际模型相同。

提供 PostgreSQL 专用 POST /api/knowledge/reindex?limit=20，每次最多重建 20 个旧块。逐块请求并原子更新；条件更新校验原始文本与来源，避免覆盖并发修改。失败保留旧向量并返回失败块 ID，可重试；不删除原始文档。该维护接口用于本地开发，公开部署前需要鉴权。

本阶段不引入 Rerank、MCP、复杂 Agent 编排，不声称完成中文分词或检索质量评测。旧的超长块不自动拆分重建，需要重新导入以应用新分块策略。模型下载失败时明确报告本地模型验证限制。

## 验收

- 本机 HTTP 服务验证向量请求与异常响应校验。
- 分块测试覆盖长段落、段落边界、重叠及空文本。
- Docker 集成测试覆盖来源隔离、重建、原文保留与多块存储。
- 使用本地 Qwen3 完成真实向量、PGVector 与 DeepSeek 联调。
