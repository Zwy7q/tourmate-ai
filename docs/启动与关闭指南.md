# TourMate AI 自己启动与关闭项目

适用于当前配置：DeepSeek负责对话与行程，百炼 `qwen3.7-text-embedding-flash` 负责向量；PostgreSQL保存知识，Redis保存会话和行程。无需启动Ollama，无需下载本地模型。

项目目录：`D:\codexspace\codespace02\projects\tourmate-ai`。下列命令在PowerShell中执行，各终端都明确指定目录，照着复制即可。

## 一、启动前只需确认这些

打开Docker Desktop，等待它进入运行状态。环境要求Java 21、Maven 3.9+、Node.js 22.12+（或24）。可以执行：

```powershell
java -version
mvn -version
node -v
npm -v
docker info
```

根目录 `.env` 已有你的配置，不必每次填写。需要有 `DEEPSEEK_API_KEY` 和 `DASHSCOPE_API_KEY`。对话型号为 `deepseek-chat`；向量默认是 `qwen3.7-text-embedding-flash`。不要把Key发到聊天或写入前端。

## 二、先启动数据库

终端1执行：

```powershell
cd D:\codexspace\codespace02\projects\tourmate-ai\infra
docker compose up -d
docker compose ps
```

看到postgres与redis为healthy后，再启动后端。这个终端可以保留作检查，也可以关闭；容器仍会在后台运行。

| 服务 | 端口 | 保存什么 |
| --- | --- | --- |
| PostgreSQL / PGVector | 5433 | 资料元信息、文本块、向量 |
| Redis | 6380 | 最近对话、行程及版本 |

这里只启动postgres和redis。`ollama` 属于可选profile，当前云端向量方案不需要它。

## 三、启动MCP工具服务

新开终端2执行，并保持窗口运行：

```powershell
cd D:\codexspace\codespace02\projects\tourmate-ai\tools-server
mvn -s ../backend/maven-central-settings.xml spring-boot:run '-Dspring-boot.run.jvmArguments=-Djava.net.useSystemProxies=true'
```

看到 `Started ToolsServerApplication` 和18090端口启动记录，就表示工具服务就绪。它提供天气和演示订单查询，地址为 `http://127.0.0.1:18090/mcp`。这是MCP协议端点，直接用浏览器打开不一定会显示页面。

JVM参数让天气请求使用Windows系统代理；如果电脑没有配置系统代理，也可以保留该参数。不要把代理软件端口写进项目源码。

## 四、启动Java后端

新开终端3执行，并保持窗口运行：

```powershell
cd D:\codexspace\codespace02\projects\tourmate-ai\backend
mvn -s maven-central-settings.xml spring-boot:run '-Dspring-boot.run.profiles=deepseek,postgres,redis,embedding,agent'
```

看到 `Started TourmateApplication` 和8080端口启动记录，后端就绪。五个profile的含义：

| profile | 作用 |
| --- | --- |
| deepseek | 启用DeepSeek及行程模型 |
| postgres | 使用真实PostgreSQL知识库 |
| redis | 使用Redis会话和行程存储 |
| embedding | 使用百炼云端向量模型 |
| agent | 启用Alibaba ReAct Agent和MCP客户端 |

不要把 `embedding` 写成 `local-embedding`，也不要同时启用它们。后端启动时会连接工具服务，所以必须先完成上一步。

## 五、启动Vue前端

新开终端4执行：

```powershell
cd D:\codexspace\codespace02\projects\tourmate-ai\frontend
npm run dev
```

第一次在新电脑使用，或依赖文件更新后，先在frontend目录执行一次 `npm ci`。当前电脑已经安装过，不需要每次重装。

打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。页面左下角应显示“后端服务已连接”。保持前端终端运行。前端通过Vite把 `/api` 请求转发到8080，不需要给前端填写模型Key。

## 六、确认启动成功并试用

可以在终端1或另一个PowerShell中执行：

```powershell
Invoke-RestMethod http://127.0.0.1:8080/api/health
Invoke-RestMethod http://127.0.0.1:5173/api/health
```

两者均返回 `status: UP`，说明后端HTTP服务和前端代理可用；模型、资料和工具还需通过实际问题验证。

建议按顺序测试：

1. 知识库：搜索“前端联调演示景区学生票”，应该能找到之前导入的演示资料。
2. 智能客服：问“前端联调演示景区学生票多少钱，需要什么证件？”；应根据资料回答，并出现引用。
3. 天气：问“杭州明天天气怎么样？”，应显示真实预报日期和来源；上游网络不可用时会提示失败。
4. 订单：问“查询演示订单 DEMO-1001”，结果必须标注虚构演示。
5. 行程：在“行程助手”输入“明天去杭州玩两天，单人预算1000元，喜欢自然风景，慢节奏。”；再试“第二天全部改为室内活动”。
6. 确认：客服输入“我要退票”，点击“确认演示退票”后还会弹出二次确认。这只是演示，不退款、不联系票务平台。

当前电脑已有知识库和行程景点资料，无需每次导入。新环境需要演示景点时，在根目录执行：

```powershell
cd D:\codexspace\codespace02\projects\tourmate-ai
.\scripts\import-itinerary-demo.ps1
```

该脚本导入6个虚构杭州景点，不是实时景区数据。普通PDF上传用于客服知识，不能自动变为具备价格和闭馆日的结构化行程景点。

只有切换向量模型后才需要重新生成旧资料向量，不用每次启动都重建：

```powershell
Invoke-RestMethod 'http://127.0.0.1:8080/api/knowledge/reindex?limit=20' -Method Post
```

有更多资料时分批调用，直到remaining为0；如出现失败先排查原因。当前9个资料块已在2026-10-14切换百炼后重建完成。

## 七、怎么关闭

先在前端、后端、工具服务这三个运行中的终端各按一次 **Ctrl+C**。如果PowerShell询问是否终止批处理，输入Y并回车。然后停止容器：

```powershell
cd D:\codexspace\codespace02\projects\tourmate-ai\infra
docker compose --profile local-embedding stop
docker compose --profile local-embedding ps -a
```

这里加local-embedding是为了同时停掉以前可能启动过的Ollama。`stop`保留容器和数据卷，不删除数据库、资料或已下载模型。不要使用 `down -v`，它会删除本项目的数据卷。

关闭后网页无法访问是正常现象。不要只关浏览器：关页面不会停止Java、Vite或容器。其他项目的容器不需要停止。

Redis对话只保留最近20条消息，最近写入后的有效期为24小时；行程保存有效期也是24小时。停止服务不会暂停过期计时。知识库保存在PostgreSQL数据卷中；退款令牌只存在后端内存，5分钟内单次有效，后端重启后丢失。

## 八、常见问题怎么定位

| 现象 | 优先检查 |
| --- | --- |
| `docker info` 报无法连接 | Docker Desktop是否启动完成 |
| `no configuration file provided` | 是否在infra目录执行compose，或显式传 `-f` 指定文件 |
| 后端提示MCP未就绪 | 先启动tools-server，确认18090端口，再启动后端 |
| 数据库连接失败 | `docker compose ps`，postgres与redis是否healthy，5433/6380是否被占用 |
| 前端提示后端未连接 | 8080后端是否启动；Vite代理是否被旧环境变量指向18084 |
| 401或欠费 | 检查对应平台Key、地域、余额；百炼向量和DeepSeek对话是两个账户配置 |
| Ollama下载TLS超时 | 当前配置无需Ollama，跳过下载；确认后端使用embedding profile |
| 行程提示缺资料 | 检查是否导入该城市结构化景点，切模型后是否完成重建 |
| 修改代码后打包无法删除jar | 正在运行的jar占用target文件，先Ctrl+C停止后端再打包 |
| `Port ... already in use` | 已启动过一份服务，先停止原终端中的进程，避免重复启动 |

如果前端终端以前设置过其他后端端口，可在启动前恢复默认值：

```powershell
Remove-Item Env:TOURMATE_BACKEND_URL -ErrorAction SilentlyContinue
npm run dev
```

如需从任何目录检查本项目容器，可执行：

```powershell
docker compose -f D:\codexspace\codespace02\projects\tourmate-ai\infra\docker-compose.yml --profile local-embedding ps -a
```
